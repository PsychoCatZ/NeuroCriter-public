# Пример самостоятельного развёртывания

Файлы в этой папке — шаблоны для вашей установки. Они не содержат адреса
рабочего сервера или данных какого-либо питомца.

## Подготовка

1. Подготовьте Linux-сервер с Python 3.12, systemd и Caddy.
2. Создайте отдельного пользователя `nedodelok`, каталоги `/opt/neurocritter`
   и `/var/lib/neurocritter`; каталог данных доступен только пользователю сервиса.
3. Скопируйте проект в `/opt/neurocritter`, создайте виртуальное окружение
   `/opt/neurocritter/server/.venv`, установите `server/requirements.txt`.
4. Скопируйте `neurocritter.env.example` в `/etc/neurocritter.env`, задайте
   права `600`, владельца root. Впишите свой токен (случайный, не короче 16 знаков),
   выбранного провайдера, ключ, модели, бюджет и `NEUROCRITTER_VAPID_SUB`.
   Режим разработки не включайте. Ключи и токен в Git не добавляйте.
5. Установите `neurocritter.service` в `/etc/systemd/system/`, затем выполните
   `systemctl daemon-reload` и `systemctl enable --now neurocritter`.
6. В `Caddyfile` замените `pet.example.com` своим доменом и настройте его DNS.
   Приложение слушает только `127.0.0.1:8000`; наружу направляется HTTPS через Caddy.
   Согласуйте сетевые правила с другими службами вашего сервера.

Проверьте HTTPS, отказ в доступе к данным без токена, создание питомца, сохранение
после перезапуска и уведомления на целевом устройстве. Не открывайте порт приложения
в интернет напрямую. Параметры примера адаптируйте к своей системе.

## Бэкапы

Для консистентной копии SQLite используйте backup API, например:

```sh
python3 /opt/neurocritter/deploy/backup.py /var/lib/neurocritter /var/backups/neurocritter 14
```

Скрипт сохраняет только `pet.sqlite` и удаляет старые копии сверх указанного числа.
Расписание запуска и отправку на отдельное хранилище настройте самостоятельно.
Для полного восстановления отдельно сохраните конфигурацию, VAPID, журналы бюджета
и вызовов безопасным способом. Ограничьте доступ к резервным копиям.
Проверяйте восстановление на отдельном экземпляре, без отправки уведомлений.

## Обновление

Сначала сохраните консистентную копию данных и предыдущую версию кода.
Прогоните тесты новой версии отдельно; затем обновите приложение и перезапустите
только его сервис. Проверьте доступ, состояние и журналы. При ошибке возвращайте
предыдущий код с учётом совместимости формата данных.
